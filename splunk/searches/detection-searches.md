# Splunk Detection Searches

This document contains the SPL detection searches used in the Windows SOC lab.

## 1. Windows Failed Logon Detection

Purpose: Detect failed Windows authentication attempts using Security Event ID 4625.

SPL:
index=* EventCode=4625

Event ID: 4625

SOC Use Case:
- Failed authentication
- Incorrect credentials
- Repeated authentication failures
- Password guessing
- Possible brute-force activity

Alert:
- Alert Name: SOC - Windows Failed Logon
- Type: Scheduled
- Schedule: Every 5 minutes
- Time Range: Last 5 minutes
- Trigger Condition: Number of results > 0

---

## 3. Sysmon Process Creation Detection

Purpose: Monitor process creation activity generated by Sysmon.

## 10. Suspicious PowerShell Command Detection

Purpose: Identify PowerShell activity containing commonly investigated command patterns.

SPL:
index=* sourcetype="WinEventLog:Microsoft-Windows-PowerShell/Operational" (EventCode=4103 OR EventCode=4104) ("EncodedCommand" OR "FromBase64String" OR "Invoke-WebRequest" OR "DownloadString" OR "IEX" OR "Invoke-Expression")

SOC Use Case:
- Encoded command activity
- Base64 decoding
- Web requests
- Download activity
- Dynamic PowerShell execution

A match does not automatically indicate malicious activity and should be investigated in context.

## 11. Multiple Failed Logons / Brute-Force Detection

Purpose: Identify hosts or accounts generating multiple failed authentication attempts.

SPL:
index=* EventCode=4625
| stats count as failed_attempts by host, Account_Name
| where failed_attempts >= 5
| sort - failed_attempts

SOC Use Case:
- Password guessing
- Brute-force activity
- Account misuse
- Repeated authentication failures

The threshold of 5 is used for this lab demonstration and should be tuned for a production environment.

---

## 12. Failed Logon Followed by Successful Logon

Purpose: Identify accounts that experienced both failed and successful authentication activity within the selected search period.

SPL:
index=* (EventCode=4625 OR EventCode=4624)
| stats count(eval(EventCode=4625)) as failed_logons count(eval(EventCode=4624)) as successful_logons by host, Account_Name
| where failed_logons > 0 AND successful_logons > 0
| sort - failed_logons

SOC Use Case:
- Authentication investigation
- Identifying accounts with mixed authentication activity
- Prioritizing suspicious authentication patterns

This search is an investigation starting point and does not independently confirm compromise.

---

## 13. Suspicious Process Execution

Purpose: Identify process creation involving commonly investigated Windows scripting and command interpreters.

SPL:
index=* sourcetype="WinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1 (Image="*\\powershell.exe" OR Image="*\\cmd.exe" OR Image="*\\wscript.exe" OR Image="*\\cscript.exe" OR Image="*\\mshta.exe")

SOC Use Case:
- PowerShell execution
- Command interpreter activity
- Script execution
- Suspicious process investigation

Analysts should review the process image, command line, parent process, user, execution path, timestamp, and related network activity.

---

## Detection Workflow

Windows Endpoint
→ Windows Security / Sysmon / PowerShell Telemetry
→ Splunk Universal Forwarder
→ Splunk Enterprise
→ SPL Detection Search
→ Scheduled Alert
→ Triggered Alert
→ Analyst Investigation
→ True Positive / False Positive Classification

---

## Investigation Approach

When an alert is generated, the analyst should review:

1. Timestamp
2. Host
3. User
4. Event ID
5. Process information
6. Command line
7. Parent process
8. Source and destination information
9. Related authentication events
10. Related activity before and after the event

A single event should not automatically be classified as malicious. Detection results should be correlated with surrounding telemetry before determining whether the activity is legitimate, suspicious, or malicious.
